# 2 需求分析与可行性分析

## 2.1 系统设计目标

这套系统的整体设计目标，是打造一套能在恶劣天气下高效、精准识别车辆的智能感知平台，具体有五个方面：一是能适配雾天、雨天、低光照三类恶劣天气，通过针对性图像增强改善识别效果；二是在恶劣天气下，车辆检测精度尽量接近正常天气，增强后mAP50指标有明显提升；三是具备实时处理能力，单张图像从增强到检测的耗时控制在可接受范围，满足实际使用需求；四是支持图片上传、视频分析、摄像头实时识别三种输入模式，覆盖不同场景；五是有直观的Web界面，检测一键操作、结果可视化，还能查询管理历史记录。

## 2.2 需求分析

### 2.2.1 功能需求分析

结合上面提到的设计目标，系统得具备以下这些核心功能模块，一是图像上传与管理功能，用户能通过Web页面把要检测的道路图像上传上去，系统会自动接收并存储这些上传的文件，还支持JPG、PNG、BMP等常见的图像格式；二是自动场景识别功能，系统能自动分析输入图像的视觉质量，还能识别出当前的天气条件类型，像正常天气、雾天、雨天、低光照这些都能识别到，这样就能为后续选择合适的增强策略提供依据；三是图像增强处理功能，系统会根据场景识别的结果自动挑选合适的增强算法，也能让用户手动指定增强方式，对退化的图像进行恢复和增强处理，支持的增强方式有去雾增强、去雨增强、低光照增强还有自动模式；四是车辆检测功能，系统能对增强后的图像进行车辆目标检测，把图像里的轿车、卡车、公交车、摩托车、自行车这五类车辆目标都识别出来，还会输出每辆车的类别标签和置信度分数；五是检测结果可视化与统计功能，系统会在图像上画出检测边界框和标签，还能用直观的方式展示出各类别车辆的数量统计信息；六是多模式检测支持功能，系统支持三种输入模式，其中图片模式能支持单张图像上传检测，视频模式能支持对视频文件进行逐帧处理，摄像头模式则能通过RTSP协议接入监控摄像头，实现实时检测；七是历史记录管理功能，系统会自动保存每次检测的原始图像、增强后图像、标注后图像还有检测统计后的结果，同时也支持对历史记录进行查询、查看详情和删除的操作。

### 2.2.2 非功能需求分析

非功能需求分析，一是性能方面的需求，单张图像的完整处理流程，包括上传、场景识别、增强、检测还有结果保存，得在数秒内就完成，视频流的处理也要达到能正常使用的帧率水平；二是可用性方面的需求，系统要提供简洁明了的用户界面，操作流程也得直观好懂，用户不用具备专业知识，就能把所有检测操作都完成；三是可靠性方面的需求，系统得有完善的错误处理办法，遇到无效输入、模型加载失败、文件读写异常这些情况时，能给出明确的错误提示，确保系统能稳定运行；四是可扩展性方面的需求，系统架构要做好模块化设计，这样后续就能方便地增加新的增强算法、检测模型，或者新增对其他天气类型的支持；五是兼容性方面的需求，系统后端要能兼容Windows、Linux这些主流操作系统，前端也要能兼容Chrome、Firefox、Edge等常见的主流浏览器。

## 2.3 可行性分析

### 2.3.1 技术可行性

技术可行性主要考察系统所采用的关键技术在理论层面和实践层面是否具备成熟的支撑条件，本系统在技术选型上经过了充分的调研与论证，各项核心技术均具备可靠的实现基础。

在深度学习算法层面，系统所采用的图像增强模型与车辆检测模型都来源于学术界经过充分验证的成熟方案，NAFNet 模型凭借其简洁高效的架构设计，在去雾与去雨任务上取得了优异的恢复效果，MBLLEN 与 Zero-DCE 作为低光照增强领域的代表性方法，能够在不引入额外参考信息的前提下完成画面亮度的有效提升，YOLOv8 则是当前目标检测领域的主流方案之一，在车辆检测这类通用场景中表现出了出色的精度与速度平衡，这些模型都有公开可获取的预训练权重，为本系统的快速搭建提供了便利条件。

在开发框架层面，Python 语言拥有极为丰富的算法生态，PyTorch 框架作为当前深度学习领域使用最为广泛的训练框架之一，具备完善的文档支持与活跃的社区资源，ONNX Runtime 推理引擎能够将训练好的模型统一转换为跨平台格式，摆脱了对特定框架运行环境的依赖，Flask 后端框架以轻量化的设计理念著称，非常适合本系统这种中等规模的服务型应用，MySQL 数据库作为业界应用最为广泛的关系型数据库之一，在数据持久化存储方面有着充足的性能保障。

在硬件环境层面，系统对运行设备的配置要求处于合理范围，核心推理过程可以在普通 CPU 环境下顺利完成，ONNX Runtime 提供的多线程并行优化能力能够充分利用多核处理器的计算资源，即便在不配备独立显卡的常规办公电脑上也能达到可接受的响应速度，这使得系统的部署门槛得到了有效降低。

综合以上几个方面的分析，本系统所涉及的各类关键技术都已经具备了成熟的实现条件，技术风险处于可控范围之内，技术可行性得到充分保障。

### 2.3.2 经济可行性

经济可行性需要从开发成本与运行成本两个维度进行评估，判断项目在经济层面上是否具备合理的投入产出比。

在开发成本方面，本系统所采用的全部技术方案均为开源免费工具，PyTorch、ONNX Runtime、Flask、MySQL、OpenCV 这些核心组件都可以零成本获取并用于商业或学术用途，不需要支付任何软件授权费用，预训练模型权重同样来自公开的学术资源渠道，省去了从头训练模型所需的大量算力投入与时间消耗，开发过程中所依赖的 Python 语言及其丰富的第三方库生态也均为免费开源资源，整个技术链路的构建不会产生额外的软件采购支出。

在硬件成本方面，由于系统在设计阶段就充分考虑了 CPU 环境下的运行能力，不强制要求配备高性能显卡等昂贵硬件，一台配置主流的普通服务器或者个人计算机即可满足部署运行的基本需求，对于有更高并发处理需求的场景，也可以通过水平扩展的方式增加服务节点来提升整体吞吐量，这种灵活的部署方式使得硬件投入可以根据实际使用规模进行弹性调整。

在运维成本方面，系统采用 B/S 架构设计，用户只需要通过浏览器即可完成全部操作功能，不需要在客户端安装任何专用软件，这大幅降低了后期的维护工作量与培训成本，前后端分离的架构模式也使得各部分的更新迭代可以独立进行，减少了整体维护的复杂程度。

综合来看，本系统在整个生命周期内的经济投入都处于较低水平，而系统能够带来的车辆识别效率提升与应用价值远超其开发与运行成本，经济可行性明确成立。

### 2.3.3 操作可行性

操作可行性关注的是系统的实际使用者能否在无需专业背景知识的前提下顺利地完成各项操作任务，本系统在交互设计与使用流程方面做了针对性的优化处理。

在界面设计方面，系统前端采用简洁直观的页面布局，把图片上传、视频分析、摄像头实时识别这些核心功能都以清晰的导航入口呈现在首页位置，用户进入系统后可以快速找到所需的功能模块，检测结果通过边界框标注与统计图表的方式进行可视化展示，各类车辆的识别数量与分布情况一目了然，历史记录管理功能也采用了列表式的呈现方式，支持按时间顺序浏览过往的检测记录。

在使用流程方面，系统把完整的检测过程封装为一键式操作，用户只需要完成图像或视频文件的上传这一步手动操作，后续的场景识别、图像增强、车辆检测这些环节都会由系统自动依次执行，整个过程不需要用户参与任何参数调整或算法选择的工作，当然系统也为有进阶需求的用户保留了手动指定增强方式的选项，这种默认自动化与可选定制化相结合的设计思路兼顾了不同层次用户的使用习惯。

在学习成本方面，系统的各项操作逻辑都遵循了常见的 Web 应用使用规范，文件上传通过标准的文件选择对话框完成，检测结果通过页面区域直接展示，历史记录通过点击列表项查看详情，这些交互方式都与用户日常使用其他网站的经验保持一致，不具备计算机专业背景的普通用户经过简单的尝试即可熟练掌握全部功能的使用方法。

综上所述，本系统在操作层面具备良好的易用性特征，不同类型的用户都能够以较低的学习成本完成系统的使用，操作可行性得到验证。
